# Product Requirement Document (PRD)
## Automated CLI Coding Agent UI Specification

---

## 1. PENDAHULUAN & TUJUAN
Dokumen ini mendefinisikan spesifikasi produk dan fungsionalitas antarmuka (UI) untuk **CLI Coding Agent** (aplikasi asisten pemrograman berbasis AI yang sejenis dengan Codex atau Claude CLI). 

Berbeda dengan aplikasi Terminal User Interface (TUI) yang mengambil alih seluruh layar secara penuh (*fullscreen*), aplikasi ini mengadopsi paradigma **Inline CLI Application**. Aplikasi memanfaatkan library **Ratatui** khusus sebagai *widget generator* mandiri untuk merender komponen interaktif di baris terbawah terminal (*inline buffer rendering*), sementara riwayat keluaran (*output stream*) dikelola sepenuhnya oleh *scrollback buffer* bawaan terminal sistem operasi.

---

## 2. PARADIGMA INLINE CLI & ARSITEKTUR LAYOUT
Aplikasi berjalan secara sekuensial dari atas ke bawah pada kanvas gulung (*scrollback canvas*) terminal. Komponen UI dibagi menjadi tiga blok utama berdasarkan daur hidup pencetakannya (*render lifecycle*):

### A. Banner & Capabilities Block (Static Print)
* **Sifat:** Dicetak sekali saja saat aplikasi pertama kali diinisialisasi atau dijalankan.
* **Konten:**
    * Teks selamat datang, informasi versi, dan petunjuk ringkas penggunaan perintah (`/help`).
    * Daftar kapabilitas eksternal yang aktif: **Skills** (perangkat fungsional internal aplikasi) dan **MCP Servers** (Model Context Protocol).
* **Perilaku:** Blok ini akan bergeser ke atas (*scrolled out*) secara alami seiring dengan bertambahnya riwayat percakapan di terminal.

### B. History & Response Stream Block (Sequential Print)
* **Sifat:** Dicetak secara sekuensial ke bawah mengikuti aliran data (*stream*) dari LLM.
* **Konten:**
    * **User Prompt:** Salinan teks perintah yang diajukan oleh pengguna pada sesi sebelumnya.
    * **Response Thinking:** Bagian visual yang menampilkan proses berpikir atau *reasoning tokens* dari LLM sebelum jawaban final dikeluarkan.
    * **Response Final:** Jawaban utuh, penjelasan kode, atau hasil eksekusi dari agen AI.
    * **Progress Indicator:** Indikator animasi (*spinner*) yang berjalan selama proses berpikir atau pengaliran token berlangsung.

### C. Interactive Input Box / Footer Block (Dynamic Inline Widget)
* **Sifat:** Blok interaktif setinggi **4 baris** yang diletakkan di baris paling bawah terminal saat itu. Blok inilah yang di-render menggunakan komponen *widget* Ratatui.
* **Konten:**
    * **Baris 1:** Border atas kotak berbentuk putus-putus (*dashed line*).
    * **Baris 2:** Kolom input interaktif tempat pengguna mengetik teks secara langsung.
    * **Baris 3:** Status bar dinamis yang terbagi menjadi dua kolom:
        * *Kiri (Status Lingkungan):* Menampilkan *Current Working Directory* (cwd) dan nama *Git Branch* yang sedang aktif saat itu.
        * *Kanan (Status Model):* Menampilkan nama *Provider*, nama *LLM Model* yang digunakan, serta persentase dan batas maksimal penggunaan token konteks (`%/max_tokens`).
    * **Baris 4:** Border bawah kotak berbentuk putus-putus (*dashed line*).

## 3. LOGIKA MANAJEMEN KURSOR & SIKLUS HIDUP RENDER

Untuk menciptakan efek kotak input yang statis namun interaktif di baris terbawah tanpa merusak riwayat teks di atasnya, aplikasi wajib menerapkan siklus manajemen kursor (*cursor adjustment*) sebagai berikut:

```
[Inisialisasi Aplikasi]
           │
           ▼
┌────────────────────────────────────────────────────────┐
│ 1. Cetak BANNER & SKILLS (println!)                     │
│ 2. Cetak 4 baris kosong (\n\n\n\n) sebagai padding     │
└────────────────────────────────────────────────────────┘
           │
           ▼
┌────────────────────────────────────────────────────────┐
│ FASE INTERAKTIF (Looping per Input Karakter)           │
├────────────────────────────────────────────────────────┤
│ 1. Mundur 4 baris ke atas (MoveUp(4))                  │
│ 2. Bersihkan area 4 baris ke bawah                     │
│ 3. Gambar Mini Buffer Ratatui (Size: TermWidth x 4)     │
│    - Border Dashed                                     │
│    - Input Text                                        │
│    - Status Bar (cwd, branch, provider, model, tokens) │
│ 4. Cetak Buffer ke stdout                              │
│ 5. Pindahkan kursor berkedip ke Baris 2 Kotak Input   │
└────────────────────────────────────────────────────────┘
           │
     [Tekan Enter]
           ▼
┌────────────────────────────────────────────────────────┐
│ FASE EKSEKUSI & STREAMING                              │
├────────────────────────────────────────────────────────┤
│ 1. Pindahkan kursor ke Baris 4 (Paling bawah)          │
│ 2. Jalankan println!() untuk mengunci Kotak Input      │
│ 3. Cetak "Thinking Stream" secara sekuensial (Dimmed)  │
│ 4. Cetak "Final Response Stream" hingga selesai        │
│ 5. Cetak 1 baris kosong & 4 baris kosong untuk padding │
└────────────────────────────────────────────────────────┘
           │
           └─────► (Kembali ke FASE INTERAKTIF untuk sesi baru)
```

### Detail Pergerakan Kursor Pada Fase Interaktif:
1.  **Penaikan Kursor (`MoveUp`):** Setiap kali terdeteksi penekanan tombol (*key event*) dari pengguna, aplikasi mengirimkan perintah ANSI `MoveUp(4)` untuk menaikkan posisi cetak terminal ke awal baris kotak input sebelumnya.
2.  **Pembersihan Area (`Clear`):** Melakukan pembersihan area dari posisi kursor ke bawah (*Clear dari Cursor Down*) untuk menghapus render lama dan mengantisipasi perubahan ukuran lebar terminal (*terminal resizing*).
3.  **Pengalihan String Buffer:** Ratatui menggambar seluruh struktur kotak input ke dalam objek memori `Buffer` internal berukuran $X 	imes 4$. Objek ini kemudian dikonversi menjadi string berbasis ANSI escape codes untuk dicetak langsung ke `stdout`.
4.  **Penempatan Kursor Mengetik (`MoveTo`):** Setelah string buffer dicetak, kursor terminal secara default akan berada di baris paling bawah (Baris 4). Aplikasi harus memindahkan kursor tersebut secara manual kembali ke Baris 2, tepat di sebelah kanan karakter terakhir dari teks yang sedang diketik oleh pengguna, agar indikator ketik tetap akurat.

## 4. PERSYARATAN STYLING & BATASAN TEKNIS TERMINAL

### A. Tampilan Teks Proses Berpikir (Response Thinking)
* **Persyaratan:** Teks hasil pemikiran (*reasoning/thinking tokens*) harus memiliki visualisasi yang lebih tipis atau redup (*lighter font style*) dibandingkan dengan teks jawaban akhir.
* **Batasan Teknis:** Terminal standar tidak mendukung modifikasi berat font (*font weight*) kustom seperti varian *Light* atau *Thin*.
* **Solusi Desain:** Aplikasi wajib menggunakan atribut **`Modifier::DIM`** (atau kode ANSI Faint/Dim) dan/atau mengaplikasikan warna abu-abu tua spesifik (misalnya `Color::Indexed(242)`) untuk memberikan impresi visual teks yang redup dan tipis.

### B. Desain Kotak Input & Status Bar
* **Gaya Garis:** Menggunakan tipe border putus-putus (`BorderType::Dashed`) selama mode pengetikan aktif. Saat pengguna menekan *Enter*, aplikasi dapat mengubah tipe border kotak tersebut menjadi garis lurus biasa (`BorderType::Plain`) untuk menandakan secara visual bahwa sesi input tersebut telah dikunci dan bersifat *read-only*.
* **Pembagian Informasi Status Bar:** Menggunakan fungsionalitas `Layout` dari Ratatui untuk membagi Baris 3 menjadi dua segmen dengan akurat tanpa kalkulasi spasi manual, memanfaatkan `Constraint::Percentage` atau `Constraint::Min` untuk memastikan status bar adaptif terhadap perubahan lebar terminal.

### C. Penanganan Konkursi (Concurrency)
* Aplikasi wajib memisahkan *thread* utama (yang bertugas menangani input keyboard pengguna dan merender kotak input) dengan *background worker thread* yang bertugas melakukan panggilan API ke penyedia LLM.
* Setiap kali token baru diterima dari *stream* LLM (baik token *thinking* maupun *final*), *background thread* mengirimkan sinyal ke *main thread* untuk mencetak token tersebut secara langsung ke `stdout` tanpa mengganggu stabilitas visual terminal.

## 5. REKOMENTASI STRUKTUR DATA (APPLICATION STATE)

Dokumen perencanaan arsitektur harus memuat minimal struktur data *state* yang ramping untuk mengelola komponen *dynamic inline* ini, antara lain:

1.  **Input State Management:**
    * `input_buffer`: String (Menyimpan teks yang sedang diketik).
    * `cursor_index`: Unsigned Integer (Menyimpan posisi kursor horizontal di dalam teks).
2.  **Environment Metadata Context:**
    * `current_working_directory`: String (Diambil dari sistem operasi).
    * `git_branch_name`: Opsional String (Diambil dari pembacaan repositori `.git` lokal jika tersedia).
3.  **LLM Configuration Context:**
    * `active_provider`: String (Contoh: Anthropic, Gemini, OpenAI).
    * `active_model`: String (Contoh: Claude 3.5 Sonnet, Gemini 1.5 Pro).
    * `token_usage_count`: Unsigned Integer.
    * `max_token_limit`: Unsigned Integer.
